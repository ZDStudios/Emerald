On the difficulty of measuring a browser

Resident set size is the number everyone quotes and the number that means least. It counts every physical page a process has mapped, including pages shared with every other process in the same tree, which for a browser means the engine library is counted once per renderer.

Proportional set size divides each shared page by the number of processes sharing it. It is slower to collect and it is the honest number. A browser that reports RSS per tab and compares it to another browser's total is not comparing anything.

The second problem is the state you measure in. A browser that has just started has not yet allocated its caches; one that has been open for six hours has. Neither is wrong, but only one of them is what you experience, and it is usually not the one in the marketing material.

The third problem is that memory is not the cost people feel. What people feel is the machine becoming unresponsive, which is a function of pressure, swap, and how much the browser insists on doing while you are not looking at it. A browser can hold a lot of memory politely, and it can hold very little rudely.

All of which is a long way of saying: publish the method, publish the raw numbers, and say which state you measured in. Anything else is a claim, not a measurement.
